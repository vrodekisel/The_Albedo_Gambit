# Боевой интерфейс

Источник: Figma `LqyZATEUXUlSH7P1aSYlwM`, состояния Eric (22:2), Joseph (29:2), Mia (29:38), Evelyn (29:74). Использованы локальные портреты, аватары, иконки и шрифт Edu NSW ACT Foundation из `Assets/Art/UI`; лицензия шрифта лежит рядом. Иллюстрация доски из макета заменяется существующим игровым миром, интерфейс рисуется поверх него.

## Проверка в сцене

Открыть ChessRoomBlockout, нажать Play, затем T. Кликать по верхним портретам: A — Eric, B — Mia, C — Joseph, D — Evelyn. Визуальный порядок из макета: Eric, Joseph, Mia, Evelyn; номера клавиш 1–4 сохраняют порядок A–D. До первого действия выбор карточки свободен и не расходует действие. После первого действия чужие карточки блокируются до End Turn; переключение клавишами и на доске также запрещено.

Зелёные контуры — допустимые клетки перемещения. Клик по ним выполняет один ход с короткой анимацией, конь прыгает. На время анимации End Turn заблокирована; пауза замораживает движение. После перемещения контуры исчезают, в верхней подсказке указано, за кем закреплён ход. Союзники и враги блокируют линии обычного перемещения и занятые конечные клетки; конь перепрыгивает промежуточные клетки.

- Menu / Esc открывают паузу. Resume / Esc продолжают игру.
- End Turn вызывает PartyChainController.EndPreviewTurn, который делегирует BattleSession.EndPlayerTurn; при будущем подключении боевого адаптера — его EndTurn. На этапе появления противников их сторона автоматически пропускает действие: AI ещё не подключён. Это временная заглушка, а не правило окончательной игры.
- Кнопки способностей показывают сообщение `not implemented yet`. Они не применяют эффект и не расходуют ресурсы. Мана не симулируется: `— / 3`.
- T возвращает в исследование, боевой HUD скрывается.

## Повторное использование

Добавить `Assets/Prefabs/UI/BattleHud.prefab` в другую сцену и назначить её PartyChainController в поле Party. В сцене нужен один EventSystem с InputSystemUIInputModule и стандартными UI Actions. HUD не содержит комнату, доску или противников. Контроллер отряда по-прежнему отвечает за вход в режим доски.

Canvas использует Screen Space Overlay, CanvasScaler с опорным размером 2560×1440 и привязками к углам экрана. Панели, тексты, маски, кнопки и ссылки на графику сериализованы в префабе и редактируются обычными инструментами Unity. Обработчики подключаются в Bind; повторный вызов не дублирует события. BattleBoardView проверяет попадания GraphicRaycaster, поэтому клики через панель в мир не проходят.

`BattleHudSetup.Build` — явный инструмент генерации исходного префаба и установки в ChessRoomBlockout; он не запускается при импорте. Повторный запуск перезапишет ручные изменения HUD, поэтому для обычной настройки следует редактировать префаб напрямую. Не запускать генератор с несохранённой сценой.

## Границы этапа

Из технической спецификации сохранено разделение состояния, команд и представления. UI не рассчитывает перемещение, атаки, объединение или откат. Новые противники, навигация, баланс и исследовательская новизна не реализовывались на этом этапе.

Валидация: `BattleHudValidation.BuildAndPlay` в тестовой копии проекта, batchmode без `-quit` (метод завершает Unity после проверки). Проверяет реальные события кнопок, состояние и UI raycasts, сохраняет изображения в Logs. Тест использует Screen Space Camera только для снимков; префаб остаётся Overlay. Полная регрессия боя и физики — отдельный следующий этап.
