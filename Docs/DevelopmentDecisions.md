# Согласованные решения

## Правила боя

- За один ход игрок действует одним персонажем; ему доступны перемещение, основное и возможное дополнительное действие. Можно атаковать до перемещения.
- Любые действия и целый ход можно пропустить. В интерфейсе предусмотрена кнопка «Следующий ход». Игрок не обязан использовать весь бюджет действий.
- Переключение героев разрешено для просмотра. После действия A выполнить действие B в том же ходе нельзя; остаток действий принадлежит A. На следующем ходе игрока после ответа противника можно выбрать другого исполнителя. Выбранный для просмотра герой и исполнитель текущего хода хранятся отдельно.
- Следующий прототип противников — четыре чёрные капсулы, появляющиеся при начале боя. Стороны ходят попеременно: один герой игрока, затем один противник. Типы перемещения и атак противников пока не определены.
- Противники блокируют проход. Ранее согласованная способность D перепрыгивать участников сохраняется; это не разрешение заканчивать движение на занятой противником клетке.
- Союзников можно проходить насквозь, но заканчивать движение на занятой союзником клетке без доступного объединения нельзя.
- Участник в нокауте продолжает занимать клетку. Проходимость такого участника и точное условие поражения команды ещё не определены.
- Базовое условие победы — нокаут всех противников. Конкретные правила нанесения урона и перехода в нокаут ещё требуют согласования.
- В дальнейшем сюжетные бои могут завершаться после заданного количества ходов; сейчас этот вариант не реализуем.
- Пока противников нет, не считать их отсутствие автоматической победой тестового эпизода.

## Управление и интерфейс

- Целевое управление: мышь для перемещения, выбора героя, клетки и боевых действий; кнопки игрового интерфейса для команд.
- Клавиатура пока сохраняется как временный способ управления.
- Мышь, клавиатура и UI должны вызывать общие игровые команды с единой проверкой правил. Логика боя не должна находиться в обработчиках кнопок.
- Перемещение мышью при исследовании потребует команды движения к точке через навигацию; оно не сводится к замене клавиши кнопкой.
- Получен и прочитан макет боевого UI в Figma: файл LqyZATEUXUlSH7P1aSYlwM, фрейм 22:2 и состояния Joseph, Mia, Evelyn. Текущая точка остановки интеграции описана в BattleUIWorkStatus.md.

## Работа с техническими материалами

- Перед реализацией каждого технического этапа сверяться с утверждённым документом о технической составляющей игры.
- Использовать согласованные примеры кода и реализации, если они относятся к текущему этапу. Проверять условия их использования и совместимость с проектом.
- Отличать заимствованные решения от собственного способа их объединения и основной технической новизны проекта.
- Основную техническую новизну интегрировать только после сверки с её утверждённым описанием; не заменять её предположениями или стандартным решением без обсуждения.
- Пользователь предоставил оригиналы документов из чата «Файлы для разработки». Они прочитаны; требования, открытые вопросы и закреплённые GitHub-источники отражены в [TechnicalFoundation.md](TechnicalFoundation.md). Эта карта не заменяет оригиналы.

## Коммиты

- Коммиты делает пользователь. Ассистент не создаёт их самостоятельно.
- После законченного этапа ассистент предлагает момент для коммита и его название на английском языке.
